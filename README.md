# Account Takeover & Suspicious Session Behaviour Anomaly Detection

An end-to-end machine-learning portfolio project for detecting suspicious banking sessions that may indicate account takeover (ATO).

## What this project does

Instead of classifying transactions one at a time, the system models **session behaviour** across authentication, device, location, account-security, beneficiary and transaction events.

It includes:

- realistic synthetic banking event generation
- user-specific behavioural baselines
- sessionisation
- behavioural feature engineering
- Isolation Forest baseline
- dense Autoencoder
- LSTM Autoencoder for event sequences
- imbalanced anomaly evaluation
- precision, recall, F1, PR-AUC
- recall at low false-positive rates
- local explanations for flagged sessions
- Streamlit investigation dashboard
- reproducible training scripts

> The dataset is synthetic by design. Public fraud datasets generally do not provide the complete event sequences required for this ATO-session problem.

## Models

### 1. Isolation Forest
A strong unsupervised baseline trained on normal sessions.

### 2. Dense Autoencoder
Learns to reconstruct normal session feature vectors. Reconstruction error becomes the anomaly score.

### 3. LSTM Autoencoder
Learns normal event sequences. It is intended to capture suspicious combinations and ordering of otherwise legitimate-looking events.

## Suspicious behaviour scenarios

The generator includes several ATO patterns:

- new device
- new location
- impossible travel
- repeated failed logins followed by success
- password/security changes
- new beneficiary
- high transaction velocity
- unusually large transactions
- composite takeover sequences

## Quick start

Python 3.10+ is recommended.

```bash
pip install -r requirements.txt

python src/data_generation.py
python src/sessionization.py
python src/feature_engineering.py

python src/train_isolation_forest.py
python src/train_autoencoder.py
python src/train_lstm_autoencoder.py

python src/evaluate.py
streamlit run dashboard/app.py
```

The LSTM implementation uses PyTorch.

## Reproducibility

All generators and models use fixed random seeds. Thresholds are selected on a validation split and final performance is reported on an untouched held-out test split. Training metadata and evaluation results are written under `reports/`.

The exact metrics in this repository are generated by running the training scripts; no performance numbers are hard-coded.

## Important limitation

This is a controlled synthetic experiment, not a production banking fraud system. The synthetic generator makes explicit assumptions about normal behaviour and attack patterns. Real deployment would require privacy-safe historical event data, continuous model monitoring, concept-drift handling, analyst feedback, calibration, security controls and extensive validation.

## Portfolio framing

The main research question is:

> Can deviations in a user's session-level behaviour identify potential account takeover more effectively than transaction-only reasoning, particularly when false-positive rates must remain very low?

The most important comparison is not accuracy. Focus on PR-AUC, recall, precision and recall at operationally constrained false-positive rates.
